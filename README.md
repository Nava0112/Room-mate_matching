# Roommate matching

This project follows the notebook in `roommate_matching (1).ipynb`.

## Install with `uv`

Install [uv](https://docs.astral.sh/uv/getting-started/installation/) first,
then install Python 3.12, create one project virtual environment, and install
the ML and backend dependencies:

```powershell
uv python install 3.12
uv venv --python 3.12 .venv312
uv pip install --python .venv312\Scripts\python.exe `
  -r ml/requirements.txt -r backend/requirements.txt
```

If PowerShell does not allow script activation, use the environment's Python
directly instead:

```powershell
uv pip install --python .venv312\Scripts\python.exe `
  -r ml/requirements.txt -r backend/requirements.txt
```

## 1. Train and verify the ML artifacts

Run the training script with the Python interpreter managed by `uv`:

```powershell
uv run --python .venv312\Scripts\python.exe python ml/train_and_save.py
```

The script loads the live Lifestyle Preferences Dataset and uses the notebook's
synthetic fallback only when the download is unavailable. It saves the
RandomForest, KMeans, fitted scaler/encoders, and metadata in `ml/artifacts/`.
The standalone inference module loads these files without training:

```powershell
uv run --python .venv312\Scripts\python.exe python ml/predict.py `
  --profile-a profile-a.json --profile-b profile-b.json
```

The two profile files are input files and are not generated automatically.
Create them before running the inference command:

```powershell
@'
{
  "age": 23,
  "gender": "female",
  "occupation": "Student",
  "location": "Kathmandu",
  "budget_min": 10000,
  "budget_max": 14000,
  "sleep_schedule": "early_bird",
  "smoking": "non_smoker",
  "drinking": "non_drinker",
  "cleanliness": 4,
  "noise_level": 2,
  "guests_preference": "sometimes",
  "food_preference": "vegetarian",
  "pets": "okay_with_pets",
  "study_habit": "quiet",
  "interests": "Book Club|Cooking|Language",
  "gender_preference": "any",
  "room_type_preference": "any"
}
'@ | Set-Content profile-a.json

Copy-Item profile-a.json profile-b.json
```

Edit `profile-b.json` if you want to compare a different person. The saved
artifacts do not need to be regenerated for inference unless the training data
or code changes.

The RF target is a proxy generated by the notebook's rule-based formula, not
human-labelled compatibility. Scores are on a 0-100 display scale. The
ensemble uses RF 0.50, KMeans 0.20, and cosine 0.30; these are starting
assumptions, not validated optimal weights.

## 2. Run the API and frontend

The API uses SQLAlchemy and reads `DATABASE_URL`. A Neon URL should include
`sslmode=require`; credentials are never stored in source. Neon PostgreSQL is
required for every environment; the application does not use a local SQLite
database or a container-local database.
Set `ADMIN_EMAIL` before registration if one account should receive the simple
room-management permission.

```powershell
$env:PYTHONPATH = (Get-Location).Path
uv run --python .venv312\Scripts\python.exe uvicorn backend.app.main:app --reload
```

In a second terminal, activate the same environment and start the frontend:

```powershell
cd frontend
npm install
npm run dev
```

When registering through the frontend, use a password with at least 8
characters. The API validates the request body, so a shorter or empty password
returns `422 Unprocessable Entity`. You can verify the backend independently
from PowerShell:

```powershell
Invoke-RestMethod `
  -Uri http://127.0.0.1:8000/auth/register `
  -Method Post `
  -ContentType "application/json" `
  -Body '{"email":"demo@example.com","password":"password123"}'
```

If that email was already registered, use a different email or call the login
endpoint instead. A successful registration returns a bearer token.

The API loads the saved artifacts at startup and exposes `/health`, auth,
profile, rooms, admin room creation, and `/recommendations`. Recommendations
apply active status, capacity, preferred location, budget, gender restriction,
room type, strict rent, required room type, and optional no-smoking constraints
before scoring. Already joined rooms are omitted from recommendations.
Occupied rooms are ranked by average ensemble score against their current
occupants. Empty rooms are listed separately with a null score because there
are no occupants to compare.

After login, the frontend stores the session token locally and retrieves the
user's database-backed membership. A joined user sees the current room and
roommates first, cannot join another room, and can leave only through the
explicit **Leave room** action. **Show All Rooms** is a directory of every
stored room, including full or inactive rooms; it never bypasses backend
eligibility checks.

The backend creates the schema on startup and adds a unique database index on
`room_memberships.user_id` so one user can belong to only one room. If an old
database already contains duplicate memberships, remove or reconcile those
duplicates before restarting so the index can be created.

Run focused backend tests with:

```powershell
.\.venv312\Scripts\python.exe -m unittest discover -s .\backend\tests -v
```

### Seed dummy rooms

To add approximately 50 repeatable demonstration rooms, including Chennai
case variants, empty rooms, occupied rooms, and isolated demo occupant
profiles, stop the API
temporarily or use a second terminal from the project root:

```powershell
$env:PYTHONPATH = (Get-Location).Path
uv run --python .venv312\Scripts\python.exe python backend/seed_rooms.py
```

The script uses `DATABASE_URL` when it is set. It is safe to run repeatedly:
rooms with the same names and demo occupants are not duplicated. Demo
occupants use `example.invalid` accounts and are never attached to real users.
Verify the imported rooms with:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/rooms
```

To initialize and seed the Neon database from the connection string in the
project `.env`, make sure the `.env` contains `DATABASE_URL=...` with the Neon
`sslmode=require` parameter. The backend loads `.env` automatically, creates
the SQLAlchemy tables if they do not exist, and inserts the demonstration rooms
into Neon:

```powershell
$env:PYTHONPATH = (Get-Location).Path
uv pip install --python .venv312\Scripts\python.exe -r backend/requirements.txt
uv run --python .venv312\Scripts\python.exe python backend/seed_rooms.py
```

Never commit or paste the real `.env` contents. The seed command does not
print the database URL.

Room discovery normalizes whitespace and casing for comparisons but does not
equate different cities. `Find Rooms` uses the saved profile, applies inclusive
budget bounds and other hard filters on the backend, and returns occupied
eligible rooms ranked by the saved ensemble before empty eligible rooms.
`Expand Search` only adds the explicitly configured alternative locations and
labels them separately. results are paged with **Load More**; empty rooms show `You are the first one`
rather than a fabricated score.

## Docker and Render

`docker-compose.yml` provides the API and Vite frontend. It does not start a
local database; configure the Neon `DATABASE_URL` from `.env`:

```powershell
docker compose up --build
```

For Render, connect the repository, create a Web Service using `render.yaml`,
set `DATABASE_URL` to the Neon connection string and `CORS_ORIGIN` to the
frontend URL, then deploy a separate Render Static Site from `frontend` with
`npm install && npm run build` and publish directory `dist`. Set
`VITE_API_URL` to the API URL when building the static site. Deployment is
not claimed here because it requires the user's Render and Neon accounts.
